Compute Match — Roles, Permissions and Access Control

Personas and the roles behind them

Compute Match uses Keycloak realm roles. The frontend turns roles into feature scopes, and the backend checks scopes on each API call.

Persona Keycloak roles (examples) Notes
Customer / Offtaker customer, customer_account_manager, Starfleet variants such as customer_consumer, customer_tech_admin Self sign-up users get default-roles-customer
NCP business user provider, provider_business_user Can manage inventory and act on reservations. Members of the Keycloak group offering-validator receive magic-link emails
NCP basic user provider_basic_user Read-only NCP access; never receives magic links
Platform Admin platform_business_admin, platform_business_admin_super_user, platform_business_admin_ops_user, platform_customer_provider_am Cross-NCP visibility, review and onboarding
Account managers account_manager_consumer, account_manager_provider The only roles allowed to belong to more than one organization
Operations / system operations, systems User activation, service accounts
Analytics superset_users, superset_admins, superset_dashboard_viewers Superset access

Feature scopes

Scopes are defined in backend/infrastructure/driving/http/routers/scopes.py and frontend/src/services/auth/accessControl/scopes.ts.

Scope Allows
view_capacity Browse GPU offerings and availability, read reference data
create_reservation_request Submit reservation and custom requests
requester_view_reservation_request See your own requests (My Requests)
requester_manage_reservation_request Cancel your own requests
send_request_multiple_provider Use the Send request to multiple NCP’s toggle
view_provider_inventory NCP views own inventory
manage_inventory Upload capacities, add or delete offerings (gates /provider/gpu-capacities-upload)
approver_view_reservation_request NCP sees reservation requests
approver_manage_reservation_request NCP accepts, rejects, contracts (gates the split Manage reservation view)
approver_view_custom_reservation_request / approver_manage_custom_reservation_request View and move custom requests (Platform Admin)
review_capacity Accept or reject future capacity uploads (gates /provider/review-future-capacities)
manage_ncp Onboard NCPs and review access requests (gates /provider/ncp-onboarding)
global_capacity_view Global Capacity Explorer (gates /provider/global-capacity)
accept_contract_extension Extend acceptance or contract deadlines
notification:send, capacity:sync, reservation-request:write Service-account scopes used by the Temporal worker

Organization scoping

  • Every user belongs to a Keycloak Organization. NCP offerings carry provider_organization_id, so NCP users only see their own organization’s inventory and requests.
  • Platform Admins see across all NCPs.
  • Only account-manager roles may be in multiple organizations (enforced by the multi-org-policy Keycloak extension).
  • One organization exists per Salesforce partner account; NCP organization names come from the Salesforce account name.

Customer confidentiality

NCPs may see a customer’s organization name blurred and labelled Confidential until engagement. Contracted prices are only visible to NCPs, platform account managers and admins.

Account status gates

After login, the backend middleware and frontend middleware check, in order:

  1. Access denied — identity verified but not authorized (for example personal email domain, missing role). User is pinned to /access-denied.
  2. Access pending — the user’s email domain belongs to an NVIDIA partner but the NCP has not been onboarded yet. An access request is created and the user waits on /access-pending until a Platform Admin approves.
  3. User status PENDING — account awaiting activation; user sees /user-status-pending (“Thanks for Signing up”).
  4. Profile incomplete — user must fill Complete Your Profile (first name, last name, organization name, phone).
  5. Terms not accepted — a blocking modal requires scrolling the Terms and Conditions, ticking “I have read and agree to the Terms and Conditions” and clicking Accept & Continue.

User account statuses are ACTIVE and PENDING.

Why is a menu item missing?

Menu items appear only when you hold the matching scope. For example, Upload Capacities needs manage_inventory; Global Capacity Explorer needs global_capacity_view. If something is missing, ask your Platform Admin to grant the role. NCP basic users (provider_basic_user) are read-only by design and are sent to the table view instead of the split Manage reservation view.
