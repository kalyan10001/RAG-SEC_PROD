Compute Match — Temporal Workflows and Schedules

Workflows are defined in shared/workflows/ and run by the worker in workflow_worker/ (main.py registers workflows, activities and schedules). Activities call the backend System APIs; the backend owns the domain logic.

Summary

Workflow Trigger Business purpose
ReservationRequestWorkflow Backend, when a request is created (workflow id = request id) Orchestrates a reservation request end to end
OfferingLifecycleWorkflow Child of the above, one per routed NCP offering Magic link, acceptance window, contract window, reminders
CsvImportWorkflow Backend, on capacity CSV upload (csv-import-{job_id}) Validate, import, wait for admin review of future capacity
ProviderOnboardingWorkflow Backend, on NCP onboarding CSV upload Create NCP organizations and users
InProcessAlertWorkflow Schedule in-process-requests-alert-daily, cron 0 9 * * * UTC Daily admin digest of In Process offerings near deadline
AuditRetentionWorkflow Schedule audit-retention-daily, cron 30 3 * * * UTC Delete audit log rows older than about 395 days
SfdcCreateBatchWorkflow (mode create) Schedule, default 0 5 * * * UTC Create Salesforce Offtake records from the outbox
SfdcCreateBatchWorkflow (mode status) Schedule, every 2 minutes Push status updates to existing Offtakes
SfdcPartnerDomainSyncWorkflow Schedule 20 2,14 * * * (twice daily) Refresh partner email domains from Salesforce

ReservationRequestWorkflow

  1. Send “request received” email to the customer.
  2. Wait for signal routed_to_providers or reservation_request_closed. Open/custom requests wait indefinitely.
  3. On routing, start one child OfferingLifecycleWorkflow per offering.
  4. Wait until any child is Contracted, all children finish, or the parent is closed.
  5. If one contracts: cancel siblings (superseded) and approve the request.
  6. If all expire: send one consolidated customer expiry email and expire the request.
  7. Closure reasons send emails: Cancelled (customer + NCPs), Rejected, Matched, Unserviceable.

Signals: routed_to_providers, reservation_request_closed. Child workflow retry up to 100 attempts; expire activity 20 attempts over about 75 minutes.

OfferingLifecycleWorkflow

  1. Send the magic-link email (critical retry policy).
  2. Acceptance phase (7 days by default): reminder 3 days before; on timeout expire the offering and email the NCP.
  3. On provider_accepted: send the introduction email; start the contract phase (45 days).
  4. Reminder 3 days before contract expiry; on timeout expire and email.
  5. On offering_contracted: send contracted email. On reject or cancel: handle and email (superseded if a sibling won).

Signals: provider_accepted, acceptance_expiry_extended, contract_expiry_extended, offering_contracted, offering_rejected, offering_cancelled.

CsvImportWorkflow

VALIDATING → IMPORTING → (if future rows) PENDING_REVIEW: email admins and wait for approve_import / reject_import → activate or reject offerings → email the NCP. Activities: validate_csv, execute_atomic_import, activate_offerings, reject_offerings, update_import_job_status, notify_admin_for_review, notify_provider_result. Workflow max attempts 1; import activities 3 attempts.

ProviderOnboardingWorkflow

validate_provider_csv → execute_provider_onboarding (30-minute timeout) → notify_onboarding_complete (sent even on failure). 3 attempts; validation errors are not retried.

Salesforce workflows

  • SfdcCreateBatchWorkflow drains the salesforce_create_sync outbox. Create mode retries 13 times every 5 minutes; status mode runs once per tick. Gated by SFDC_SYNC_ENABLED; when false, schedules are deleted and the workflow is not registered.
  • SfdcPartnerDomainSyncWorkflow is gated by SFDC_PARTNER_DOMAIN_SYNC_ENABLED. It refuses empty or suspiciously shrunk snapshots so partners are not mass-demoted.

Retry policies (shared/workflows/workflow_common/retry.py)

Policy Budget Used for
NOTIFICATION_RETRY_POLICY 5 attempts, ~2.5 min Ordinary email
CRITICAL_NOTIFICATION_RETRY_POLICY 10 attempts, ~25 min Magic-link email
STATUS_UPDATE_RETRY_POLICY 5 attempts, ~1 min Intermediate import status
TERMINAL_STATUS_UPDATE_RETRY_POLICY 8 attempts, ~20 min Final import status

Abandoned steps increment clustruffle_workflow_activity_abandoned and can be queried with get_abandoned_steps.
